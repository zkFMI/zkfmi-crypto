### S2 中核モジュール（目標 60 分）
すべて serde 対応、`deny_unknown_fields`、未知の suite や version は閉じて拒否する。
- `suite`: 閉じた enum `SuiteId` と版。現行: Ed25519、FrostRistretto255、PedersenRistretto255、BulletproofsRistretto255、X25519Tls13、Sha256、Sha512、Shake128。耐量子: MlKem768、MlDsa65、MlDsa44、SlhDsaSha2_128s。ハイブリッド: X25519MlKem768、Ed25519MlDsa65。各 suite に `post_quantum: bool`、`purpose`（Signature / Kem / Commitment / Proof / Hash / Transport）、公開鍵と署名または暗号文のバイト数を持たせ、上の FIPS 定数とテストで一致確認する。
- `key`: `ParticipantId`（不変）、`KeyId`、`KeyPurpose`（Quote、SettlementInstruction、KeyRotation、Governance、Transport、Attestation など。用途分離のため）、`KeyRecord { participant_id, key_id, suite, key_version, public_key, not_before, not_after, revoked_at, rotation_proof, dekyx_binding }`、`KeyRegistry`（検索、失効、有効期間の判定、旧鍵から新鍵への更新証明の検証）。更新証明は旧鍵で新鍵を署名し、新鍵で旧鍵 ID を署名する双方向。時刻は u64 秒で、閉区間か開区間かをコードとテストで明示する。
- `canonical`: 計画書 4.2 の正規署名対象 `SigningPreimage { protocol, protocol_version, network_id, deployment_id, contract_id, tx_kind, object_ids, sequence_or_nonce, expires_at, suite, body_hash }` の決定論的エンコード。長さ前置、固定幅整数、先頭にドメイン `ZKFMI:CANONICAL:v1`。golden bytes テストを 3 ケース以上、16 進で固定。同じ本文でも用途が違えば preimage が違うテスト。
- `traits`: `Signer`、`Verifier`、`KemEncapsulator`、`KemDecapsulator`、`ProofVerifier`、`CryptoProvider`（suite から実装を解決。未登録は拒否）。すべてバイト列 API。
- `hybrid::signature`: `HybridSignature { classical, pq }`、Ed25519 と ML-DSA-65。検証は両方成功のときだけ受理。片方失敗、欠落、順序入替を拒否。ML-DSA の FIPS 204 context には用途タグ（KeyPurpose と suite）を入れる。
- `hybrid::kem`: X25519 と ML-KEM-768 の結合。共有秘密は HKDF-SHA256 で、salt はドメイン、ikm は `ss_x25519 || ss_mlkem || ct_x25519 || ct_mlkem || suite_id`。片方の秘密だけでは復元できないこと（片方を差し替えると鍵が変わること）をテストする。X25519 は curve25519-dalek 4.1.3 か x25519-dalek 2 系。版を固定して明記。
- `backend`: ed25519-dalek 2.x、ml-dsa 0.1.1、ml-kem 0.3.2。秘密鍵は zeroize。
