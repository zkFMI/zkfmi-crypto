# Portable C interoperability vectors

Public deterministic development vectors, never operational keys or entropy.
The exact reference is [BearSSL](https://www.bearssl.org/git/BearSSL), commit
`7bea48e5e850ab4cafbe68d3765cdaba13a86d6f`, MIT (`License.bearssl.txt`).

- `bearssl-x25519-known-answer.bin`: 32-byte nonuniform RFC7748 seed, recipient
  public key, ephemeral public key and shared secret (128 bytes total).
  Generated by `research/cosnark-trial/vendor/x25519-encapsulation-circuit.c`
  with `PQC_REFERENCE_KAT`. The seed's nonuniform bytes make a mistaken
  little-/big-endian scalar adapter observable. SHA-256:
  `d20082c2a0628bb76ad67950cf493783c91356cf69e0c15507c050d9bcde44f5`.
- `bearssl-envelope-known-answer.bin`: combined key (32), ciphertext (232),
  tag (16). Generated by `recipient-envelope-circuit.c` with
  `PQC_REFERENCE_KAT`. Fixed byte values are x shared=11, pq shared=22,
  KEM ciphertext=33, nonce=44, recipient=55, context=66, plaintext=77, at
  the exact protocol widths. KEM ciphertext/recipient are **not valid KEM
  objects**: this tests the HKDF/AAD/AES-GCM arithmetic boundary only.
  SHA-256: `2a2d245fe6bc2fcff4c72c6d2e16e0508a4f5c6381d5d1a2fac32be8601f756c`.

The Rust tests compare all fields using the actual shared implementations.
Neither these tests nor successful C execution establish circuit acceptance,
full note-transaction validity or production security.
